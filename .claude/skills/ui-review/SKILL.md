대상: $ARGUMENTS

기준은 `.claude/rules/ui.md`, `docs/UI.md`, `src/app/globals.css`(토큰·키프레임·`dark` variant)다. 대상 파일과 함께 이들을 먼저 읽는다. 영역 이름이면 `src/components/<영역>/`과 그 컴포넌트를 쓰는 `src/app/` 페이지가 대상이다. `all`처럼 범위가 넓으면 영역별로 subagent를 병렬로 띄워 감사하고 결과를 모은다.

## 볼 것

- **다크/라이트**: 토큰 미사용 하드코딩 색, `dark:` 누락, 두 테마 모두에서의 대비
- **접근성**: 라벨 없는 컨트롤, 키보드로 도달·조작 불가, 색만으로 전달되는 상태, 포커스 표시 누락
- **반응형**: 좁은 폭(360px)에서 넘침·잘림, 44px 미만 터치 타겟
- **상태 완전성**: 로딩·에러·빈 상태 누락, optimistic 업데이트 실패 시 롤백
- **일관성**: 비슷한 맥락의 간격·크기·아이콘·문구가 컴포넌트마다 다른 곳, 기존 `ui/` 컴포넌트를 두고 새로 만든 것
- **오버레이**: 투명 배경 유지, 장시간 실행 시 타이머·리스너 정리
- **차트**: `ResponsiveContainer`, 다크모드 축·툴팁 색, 데이터 없음 처리

취향 차이는 이슈로 올리지 않는다. 사용자가 실제로 겪는 문제(못 읽음, 못 누름, 깨짐, 헷갈림)에 집중한다.

## 수정

이슈마다 심각도(사용 불가 / 품질 저하 / 사소)를 매기고, 앞의 두 단계는 최소 변경으로 고친다. 컴포넌트 전면 재작성, 의존성 추가, 토큰 체계 변경은 하지 않고 필요하면 제안만 한다. `pnpm build`와 `pnpm build-storybook`으로 확인한 뒤 `파일:라인`과 함께 이슈·수정 내역을 보고한다.
