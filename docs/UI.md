# UI 설계

## 페이지 구성

### 1. 홈 / 프로젝트 목록 (`/`, `/projects`)

- `/`는 `/projects`로 redirect한다.
- 목록은 내 프로젝트만 보인다. 다른 사람의 프로젝트는 목록으로 드러내지 않는다(스트리머끼리 서로의 타이머를 둘러볼 이유가 없다). 상세 화면은 소유자가 '링크 복사'로 건넨 주소로만 열린다
- 로그아웃 상태에는 `/login`과 같은 진입 화면(`SignInScreen`)을 같은 좌표에 그린다(§6). 같은 상황(로그인해야 쓸 수 있음)이 주소에 따라 다른 모양으로 보이지 않게 하려는 것이고, 1280·390·320 폭 × 라이트·다크에서 main 안 제목·소개·버튼 좌표가 0.1px까지 같다. 다른 점은 헤더 '로그인' 버튼(이 화면에서는 남긴다) 하나다. 로그인 버튼은 `next=/projects`를 들고 간다. 목록 제목 '프로젝트'·목록 API는 쓰지 않는다
- 내 프로젝트가 하나도 없으면 검색·정렬을 숨기고 '아직 프로젝트가 없습니다.'와 "첫 프로젝트 만들기"를 둔다. 전체 수는 검색어 없이 받은 목록 응답의 `total`로 정하므로 검색 결과가 0건이어도 검색창은 남는다
- 로딩: 로그인 확인과 (로그인이면) 첫 목록을 받을 때까지, 로그인 힌트(`html[data-auth]`, 콘솔 골격과 같은 장치)가 로그아웃이면 진입 화면을, 그 밖에는 제목과 검색줄 자리·첫 페이지 수(12개)만큼의 카드 골격(`ProjectCardGridSkeleton`, 실제 카드와 같은 높이)을 CSS로만 골라 그린다. 힌트로 가르는 클래스는 이 골격 단계에만 붙인다(힌트가 틀린 로그인 사용자의 실제 목록에서 제목이 사라지지 않게). 검색줄·헤더 버튼은 그 뒤 한 번에 나타난다(뒤늦게 끼어들어 아래를 밀지 않게). 모바일 카드 골격은 설명 줄을 늘 잡아 118px이라 설명 없는 카드(94px)와 다르다(받기 전에는 설명이 있는지 모르고, 골격은 통째로 바뀌어 CLS는 0이다). 본문은 첫 화면 높이를 채워(`FILL_FIRST_SCREEN`) footer가 처음부터 첫 화면 밖에 있다.
- 검색 입력, 정렬(최신순·이름순), 페이지네이션(12개 단위)
- 프로젝트 카드 그리드 레이아웃
- 각 카드: 프로젝트 이름, 설명, 타이머 상태 한 줄(실행 중·예약됨·만료, 타이머가 없으면 없음), 생성일(상대 표기). 모두 본인 프로젝트라 소유자는 표시하지 않는다
- 로그인 시 "새 프로젝트" 버튼 표시. 단 '내 프로젝트'가 0개인 빈 목록에서는 본문 "첫 프로젝트 만들기" 하나만 두고 헤더 버튼을 숨긴다(본문 버튼이 실제로 그려질 때만. 재조회(검색·페이지) 로딩 중·실패 시에는 헤더 버튼을 남긴다)(같은 동작의 강조 버튼 두 개가 경쟁하지 않게). 폼을 열면 헤더 자리에 "취소"가 나온다
- 프로젝트를 만들면 상세 화면으로 `?new=timer`를 붙여 보내고, 상세 화면은 소유자·타이머 없음일 때 타이머 만들기 창을 바로 연다. 플래그는 프로젝트·타이머·로그인 확인이 끝나면 열든 안 열든 주소에서 지운다(`src/lib/project-flow.ts`). 남겨 두면 '링크 복사'가 플래그 붙은 주소를 건넨다. 프로젝트와 타이머가 1:1이라 만들기 두 단계를 한 흐름으로 잇는다
- 반응형: 모바일 1열, 태블릿 2열, 데스크톱 3열

### 2. 프로젝트 상세 = 타이머 콘솔 (`/projects/[id]`)

핵심 페이지. 프로젝트와 타이머가 1:1이라 이 화면 하나에서 방송 중 조작을 한다. 방송 화면에 띄우는 카운트다운은 별도의 오버레이 페이지(`/timers/[id]/overlay`)이고, 이 화면에서 오버레이 설정과 URL 복사를 한다. 화면의 이름은 프로젝트 이름 하나다(타이머 제목은 오버레이의 '제목 표시'에만 쓰인다). 탭 제목은 '프로젝트 이름 | 삼루먼타이머'이고 프로젝트를 찾을 수 없으면 '찾을 수 없음 | 삼루먼타이머'다. 구분자 '|'는 서버 제목 템플릿과 같은 `site.ts`의 `TITLE_SEPARATOR` 하나이고, 클라이언트가 탭 제목을 바꿀 때는 `pageTitle()`을 쓴다.

#### 헤더
- 프로젝트 이름·설명. 소유자는 인라인 편집(`EditableText`). 저장에 실패하면 이전 값으로 돌아가고 토스트 한 줄로 알린다(4xx는 서버 사유, 5xx·네트워크는 '프로젝트 이름을 수정하지 못했습니다', 세션 만료는 그 안내만). 시청자에게는 소유자 닉네임을 함께 보여 준다
- 소유자: `OBS 오버레이`(→ `OverlaySettings` 모달)·`통계`(`/timers/[id]/stats`) 글자 버튼(타이머가 있을 때)과 더보기 버튼(`MoreMenu`: 링크 복사, 타이머 초기화(목표 유지), 프로젝트 삭제). 1:1인 대상을 '타이머 삭제'·'프로젝트 삭제' 두 개념으로 보이지 않게 결과로 부른다. 초기화는 타이머를 지우는 동작이라 기록·통계·오버레이 주소는 새 타이머에서 새로 시작하고 목표 행(기록)만 남는다. 목표 진행률은 현재 타이머의 기록으로 계산하므로 진행 중인 목표는 0부터 다시 쌓이고, 진행 중인 목표가 있으면 확인 창이 이를 알린다. 확인 창은 새 타이머의 오버레이 주소가 달라 OBS 브라우저 소스에 다시 넣어야 한다는 것까지 알린다('초기화'를 같은 타이머 재시작으로 오해하지 않게)
- 시청자: 링크 복사 아이콘 버튼만
- 더보기는 `aria-expanded` disclosure 패턴이다(`role="menu"` 아님. 결정(R30): 항목이 링크·버튼 몇 개뿐이라 menu 역할의 화살표 키 계약을 새로 만들지 않고, `role="menu"`로 바꾸지 않는다). Escape·바깥 클릭으로 닫히고 포커스는 트리거로 돌아간다. Tab으로 메뉴 밖에 포커스가 가도 닫힌다. 파괴적 항목 묶음 앞에 구분선 하나를 둔다
- 이름·설명 인라인 편집을 Enter·Esc·저장/취소 버튼으로 끝내면 포커스가 편집 버튼으로 돌아온다(다른 곳을 눌러 끝낸 경우는 그 자리에 둔다)
- 타이머만 삭제하면 화면에 남아 '타이머 없음' 상태가 되고 목표 기록은 그대로 보인다

#### 타이머가 없을 때
- 소유자에게는 '타이머를 만들면 방송 화면에 띄울 카운트다운과 OBS 주소가 생깁니다.' 한 문장과 "타이머 만들기" 버튼(`CreateTimerForm`, 제목을 프로젝트 이름으로 미리 채운다), 시청자에게는 '아직 타이머가 없습니다.'만
- 목표가 남아 있으면 그 아래 목표 섹션을 보여 준다. 타이머도 목표도 없으면 숨긴다

#### 타이머가 있을 때 (`TimerConsole`)
화면 순서: 카운트다운 → 시간 | 목표 → 최근 기록 | 잔여 시간 추이.

- 로딩: 프로젝트·로그인 확인·목표(타이머 쪽을 받은 뒤 0.5초까지만 기다린다)·타이머 목록과 콘솔 첫 데이터(`loadConsoleSnapshot`: 상세, 최근 기록 첫 페이지, 그래프)를 모두 받을 때까지 `ProjectDetailSkeleton` 하나만 두고, 그 뒤 헤더와 콘솔을 한 번에 그린다. 상위가 상세를 받지 못했으면(5xx·10초 시간 초과) 콘솔은 같은 요청을 다시 걸지 않고 그 자리에 오류와 '다시 시도'를 보이며, 다시 시도하는 동안 같은 콘솔 골격(`ConsoleSkeleton`)을 자리에 둔다. 골격은 실제 화면의 줄·칸을 베낀다(헤더 액션 버튼 셋, 모바일 clamp 크기까지 맞춘 카운트다운, 시간 카드의 입력·프리셋·확인 버튼, 목표의 '새 목표' 버튼·탭 줄·목표 한 개, 기록 5행, 그래프 상자. 제목 줄은 24px 줄 안의 막대). 로그인 확인 전이라 모양은 로그인 힌트로 고른다: `fetchMe`의 확정 결과(200·401)를 localStorage에 남기고 첫 페인트 전 스크립트가 `html[data-auth=in|out]`을 붙이며(`src/lib/auth-hint.ts`, 값이 없으면 out), 골격은 `signed-out:` CSS 변형으로만 갈라 하이드레이션이 서버 마크업과 같다. 로그아웃으로 보이면 시청자 모양(헤더에 소유자 닉네임 줄·링크 복사 아이콘, 시간 카드·목표 없음), 그 밖에는 소유자 모양이다. 로그인한 시청자는 소유자 모양을 본다. 로드 도중에는 속성을 바꾸지 않는다(보이던 골격이 바뀌며 밀리지 않게, 다음 로드부터 반영). 기록·그래프가 상세보다 0.5초 넘게 늦으면 기다리지 않고 시간 카드를 먼저 그리며, 그 자리는 기록 5행 높이·그래프 높이(h-64)로 잡아 두어 도착해도 아래가 밀리지 않는다. 본문은 첫 화면 높이를 채워(`FILL_FIRST_SCREEN`) footer가 처음부터 첫 화면 밖에 있다. 넓은 화면(lg 이상)에서 `|` 양쪽이 3:2로 나란히, 그보다 좁으면 세로로 쌓인다. 시간 카드와 목표를 첫 화면에 함께 두는 것이 목적이다.

- 카운트다운: 큰 숫자 `HH:MM:SS` + 상태 뱃지(SCHEDULED 보라 '예약됨', RUNNING 초록 '실행 중', EXPIRED 빨강 '만료'). 실행 중에는 '종료 예정' 시각(오버레이와 같은 `formatEndTime` 규칙: 오늘이면 '종료 예정 오후 1:33', 다른 날이면 '10. 6. 오후 1:33', 다른 해면 '2027. 1. 2. 오전 1:05'처럼 연도를 붙이고 초는 없음)을, 예약 상태에는 시작 예정 시각('시작 대기 중 · 2026. 10. 05. 09:00', 초 없음)을 보여 준다. 종료 예정 시각은 타이머 스냅샷이 실제로 바뀔 때(`updatedAt`·상태 변화, 시간 추가·차감·되돌리기의 낙관적 반영 포함)만 다시 잡는다. 1초 틱이나 같은 `updatedAt`으로 잔여시간만 흔들리는 폴링 응답마다 다시 재지 않는다(초 내림·응답 지연으로 분 경계에서 두 값을 오가지 않게, 오버레이와 같은 기준). 생성 시각부터 잰 경과는 다시 시작한 타이머에서 실제 진행 시간과 어긋나 보여 주지 않는다. 0에 닿으면 다음 폴링을 기다리지 않고 뱃지를 '만료'로 바꾼다. 5분 미만(임박, 라이트 amber-700)·1분 미만(긴급, 라이트 red-800)으로 올라갈 때는 색·맥동과 별개로 보이지 않는 polite 알림 한 번('남은 시간이 5분 미만입니다'·'1분 미만입니다')을 토스트의 live region에 낸다(처음부터 그 단계이거나 내려갈 때는 알리지 않는다). 긴급을 red-800으로 둔 것은 라이트에서 amber-700과 red-600의 휘도가 거의 같아서다. 숫자는 모바일(sm 미만)에서 `clamp(3rem, 17vw, 3.75rem)`로 폭에 비례해 커지고(353px부터 60px, 320px에서 약 54px) sm 이상도 60px다. 뱃지(`CountdownDisplay`의 `aside`)는 sm 이상에서 숫자 옆, 모바일에서는 숫자 아래 보조 문구 앞 같은 줄에 붙는다('실행 중 종료 예정 오후 4:37'). 숫자(276px)+뱃지가 한 줄에 들어가는지가 모바일 폭마다 갈려 353~376px에서만 뱃지가 따로 한 줄을 쓰던 것을 없앴다. 모바일 어느 폭이든 카운트다운 블록은 숫자 줄 + 24px 한 줄이다
- 동기화: 상세 API를 RUNNING 5초·그 외 15초로 폴링한다(폴링은 콘솔 한 곳에서만). 다른 기기의 조작이나 상태 전이를 감지하면 기록·그래프·목표를 다시 불러온다. 판정은 `updatedAt`이 마지막으로 반영한 값과 다르거나(1~2초짜리 변경도 잡는다), 흐른 시간을 뺀 기대값과 3초 이상 어긋나거나, 상태가 바뀐 경우다. 이 화면의 시간 추가·차감·되돌리기·지금 시작은 응답의 `updatedAt`을 저장하므로 다음 폴링이 다시 부르지 않는다. 조작 응답보다 옛 `updatedAt`의 폴링 응답(조작 직전에 떠난 요청)은 버리고, 빠른 연속 조작에서 앞 조작의 응답이 뒤 조작의 응답보다 늦게 와도 같은 규칙(시각 비교)으로 버린다(낙관적 반영·롤백은 `updatedAt`이 없어 그대로 반영). 폴링은 화면의 `updatedAt`을 `since`로 실어 보내고, `deltaSinceSeconds`가 `null`이면(그사이 추가·차감 없음: 타이머 제목 수정 등) `updatedAt`만 저장하고 기록·그래프·목표를 다시 부르지 않는다. 필드가 없으면(그사이 되돌리기 등) 바뀐 것으로 본다. 서버의 합계 조회는 `updatedAt`이 바뀐 폴링에서만 돈다. 첫 상세 조회와 폴링은 10초 안에 응답이 없으면 실패로 끝낸다(첫 조회는 콘솔 자리에 오류와 '다시 시도'). 첫 화면은 상세를 받은 뒤 기록·그래프·목표를 기다린 시간만큼 잔여를 줄여 그린다. 폴링이 404를 받으면(다른 탭·기기에서 타이머 삭제) 알림을 띄우고 '타이머 없음' 상태로 바꾼다. 폴링이 2회 연속 실패(네트워크 오류·5xx는 RUNNING 기준 약 10초. 응답 없이 멈춘 요청은 10초 시간 제한에 걸려야 실패로 세므로 약 20초)하거나 브라우저가 오프라인이면 상태 뱃지 자리를 '연결 끊김 · n초 전 기준'(회색 윤곽, 점멸 없음. 마지막으로 서버 값을 받은 시각 기준)으로 바꾼다. 좁은 화면(sm 미만)에서는 보조 문구('종료 예정')와 한 줄에 남도록 '연결 끊김'만 보인다. 새 배너·토스트는 없고 숫자는 로컬 추정값으로 계속 흐른다. 다시 온라인이 되면 곧바로 조회하고, 성공 응답을 받으면 원래 뱃지로 돌아간다. 실패 횟수와 마지막 성공 시각은 폴링 주기가 바뀌어도(낙관적 상태 변경·롤백) 이어진다. 오버레이에는 표시하지 않는다(방송 화면)
- 목표: 시간 카드 옆. 바깥 카드 없이 제목 아래 구분선 행(`GoalCard`)으로 나열한다. '진행 중' / '종료' 탭으로 나눈 `GoalCard` 목록, 소유자는 '새 목표' 버튼 → '새 목표 설정' 대화상자(`GoalForm`, `FormDialog`). 여기서 시간을 바꾸면 곧바로 목표를 다시 불러온다. 시청자에게는 목표가 있을 때만 보인다
  - 카드에는 상시 버튼을 두지 않고 소유자에게만 카드별 더보기(`MoreMenu`) 하나: 진행 중은 '목표 취소'(종료 탭에 기록으로 남음), 실패·취소로 끝난 목표는 '삭제'(기록에서 사라짐). 달성한 목표는 동작이 없다
  - 진행 중 탭의 카드에는 상태 배지를 두지 않는다(탭 이름과 중복). 종료 탭에서만 달성·실패·취소 배지
  - 방송 시간 목표는 '퍼센트 · 방송 n 경과 / 목표', 데드라인 목표는 퍼센트 대신 마감 시각·남은 기간과, 타이머 종료 예정보다 마감이 늦으면 '종료 예정보다 뒤'. 진행 막대(`role=progressbar`)의 이름은 '{목표 이름} 진행률', 읽히는 값(`aria-valuetext`)은 방송 시간 목표면 '41분 / 12시간', 데드라인 목표면 퍼센트다

#### 시간 (소유자만)
- 예약(SCHEDULED) 상태에서는 입력 대신 안내 한 줄('시작을 늦추려면 삭제 후 다시 만들기' 포함)과 '지금 시작' 버튼만 둔다. 되돌릴 수 없는 드문 동작이라 확인창(ConfirmDialog, '돌아가기'/'지금 시작')을 한 번 거친다. 이미 삭제된 타이머(404)면 '타이머 없음' 상태로 바뀐다
- 시청자 닉네임과 추가/차감 세그먼트는 md 이상에서 한 줄. 닉네임은 확인 버튼으로 적용할 때 필수, 최대 50자, placeholder "시간 변경을 요청한 시청자"(기본 닉네임이 있으면 "기본: …"). 최근 닉네임 칩, 기본 닉네임 설정·해제
- 시/분/초 칸은 대화상자 폼과 같은 규칙(`changeTimeField`)이다: 빈 값으로 시작해 placeholder '0'을 보이고, 지워도 '0'이 다시 채워지지 않으며 빈 칸은 0으로 센다. 60 이상의 분·초는 윗자리로 올린다. 프리셋 버튼 `+1시간`, `+5시간`, `+10시간`은 시/분/초 입력값에 더하기만 한다(0인 칸은 빈 칸으로 둔다). 적용은 확인 버튼으로 한다. 카드의 프리셋 행과 확인 버튼은 md 이상에서만 보인다(md 미만은 아래 하단 바가 같은 일을 한 자리에서 한다). 라벨은 늘 동사다: "시간 추가 (1시간 30분)" / "시간 차감 (…)"(변경량 표시, 차감은 `danger` 스타일). 값이 0이면 "시간 추가"로 비활성이고, 입력칸 아래 "시간을 입력하면 추가할 수 있습니다."가 이유를 알린다(`aria-describedby`)
- 분·초에 60 이상을 넣으면 자르지 않고 윗자리로 올린다(90분 → 1시간 30분, 75초 → 1분 15초. `src/lib/timer-input.ts`). 결과는 버튼 라벨이 보여 주므로 범위 안내 문구는 두지 않는다. 새 타이머 만들기의 초기 시간과 새 목표의 목표 시간도 같은 규칙이다
- 대화상자 폼(`CreateTimerForm`·`GoalForm`)의 입력 규칙: 시·분·초 칸은 빈 값으로 시작하고 placeholder '0'을 보인다(문자열 state라 지워도 '0'이 다시 채워지지 않는다). 만들 수 없는 조건(제목 없음, 시간 0, 데드라인 목표의 지난 날짜, 예약 시작의 지난 시각)이면 제출 버튼이 비활성이고 버튼 아래 한 줄('제목과 목표 시간을 입력하면 만들 수 있습니다.', '지금 이후의 시각을 고르면 만들 수 있습니다.' 등)이 이유를 알린다(`aria-describedby`). 고른 날짜·시각은 렌더 때 바로 판정하고, 대화상자를 연 채 그 시각이 지나면 그 순간 비활성으로 바뀐다(`useHasPassed`, 그 시각에만 타이머 하나). 제출 뒤 오류는 상한 초과·서버 오류용으로만 남는다. 제출 버튼은 본문 주 버튼과 같은 `md`(40px, 터치 기기 44px). 열리면 첫 입력할 칸에 포커스가 간다(새 목표는 제목, 타이머 만들기는 제목이 미리 채워져 있어 '시간')
- 입력부는 `<form>`이라 닉네임·시간 입력칸에서 Enter로 제출된다. 한국어 IME 조합 중의 Enter(`isComposing`/keyCode 229)는 제출하지 않는다
- 즉시 적용은 두 곳뿐이다: 모바일(md 미만) 하단 고정 바(`+1시간`/`+5시간`/`+10시간`, 카드 프리셋과 같은 상수·같은 표기. 차감이면 `-1시간`처럼 바뀌고 기록될 닉네임을 항상 표시)와 숫자 단축키.
- 모바일 하단 바는 주 행동 한 자리다: 시/분/초 값이 0이면 프리셋 세 개(탭 한 번에 즉시 적용), 값이 있으면 세 자리가 그 값을 적용하는 제출 버튼 하나('시간 추가 (10분)', 차감이면 빨강 '시간 차감 (…)')로 바뀌고, 적용 뒤 값이 0이 되면 프리셋으로 돌아간다. 바 높이는 그대로다. 제출 버튼은 폼 제출이라 입력란의 닉네임이 있어야 하므로, 이때 바의 캡션은 입력란 닉네임을 따른다. 숨긴 카드 확인 버튼 대신 입력칸의 Enter 제출은 그대로 된다. 두 곳 모두 같은 규칙(`resolveQuickActor`)으로 닉네임을 정한다: 입력란의 시청자 닉네임이 우선이고, 비어 있으면 기본 닉네임. 예전의 '빠른 적용' 모드 토글은 일반 모드와 차이가 직관적이지 않아 없앴다
- 닉네임이 없어도 바 버튼은 막지 않는다(W32). 누르면 닉네임 입력란으로 포커스를 옮기고 `scrollIntoView({ block: 'center' })`, 입력란 아래 `role=alert` 한 줄 '닉네임을 입력하면 바로 적용됩니다'를 띄우고, 입력란의 `aria-describedby`·`aria-invalid`로 이어 둔다(포커스 이동과 같은 틱에 뜬 alert는 낭독이 끊기고 두 번째 탭에는 다시 읽히지 않으므로 포커스가 닿을 때 이유를 함께 읽게 한다). 누른 프리셋은 기억했다가 나중에 적용하지 않는다. 기록은 실제 닉네임으로만 남긴다(고정값 '익명' 없음). 이때 캡션은 '즉시 적용 → 닉네임 칸의 이름'. 기본 닉네임 안내 '다음부터 입력 없이 바로 적용됩니다'는 '기본 닉네임으로 설정' 버튼이 보일 때 그 버튼 아래 한 줄로만 둔다(버튼은 글자색·밑줄로 설명과 구분)
- 바는 글자 입력 칸(닉네임·시/분/초)에 포커스가 있는 동안 숨긴다(`hidden`, 언마운트하지 않아 하단 여백은 그대로). 버튼·추가/차감 토글·바 버튼 포커스로는 숨지 않는다. 높이 480px 이하(가로 모드, 400% 확대)에서는 바를 `position: static`으로 카드 끝에 두고 `--quick-bar-h`를 `0px`로 둔다(하단 여백·토스트 위치가 따라온다)
- 만료(잔여 0, 카운트다운이 0에 닿은 순간 포함)에서는 추가/차감 세그먼트를 숨기고 바·카드·숫자키 모두 '추가'로 적용한다. 만료로 들어가면 선택도 '추가'로 되돌린다. 숨긴 '차감'을 남겨 두면 '+'로 재시작한 직후 같은 자리 바 버튼이 '−'로 바뀌어, 연달아 누른 두 번째 탭이 방금 더한 시간을 빼 버리기 때문이다. 만료 중 X는 아무 일도 하지 않는다. 안내는 맨 위 한 줄 '시간을 추가하면 다시 시작됩니다'. 토글에 포커스가 있는 채로 만료되면 포커스를 이 안내 줄(tabIndex -1)로 옮겨 body로 떨어지지 않게 한다(`preventScroll`로 화면은 움직이지 않는다. 이미 빈 곳 클릭 등으로 토글을 떠났으면 옮기지 않는다). 반대로 안내 줄에 포커스가 있는 채로 시간을 추가해 재시작하면 안내가 사라지므로, 돌아온 토글의 선택 항목('추가')으로 포커스를 옮긴다(같은 `preventScroll`, 안내를 이미 떠났으면 옮기지 않는다)
- 연결 끊김 중에는 버튼을 막지 않고 입력칸 아래 안내 줄 '연결이 돌아오면 적용할 수 있습니다'를 덧붙인다(모바일에도 보인다). 시간이 비어 확인 버튼이 비활성이면 비활성 이유 '시간을 입력하면 …할 수 있습니다.'는 그대로 두고 두 줄 모두 버튼 설명(`aria-describedby`)에 잇는다. 바 캡션은 모드 단서라 그대로 둔다
- 추가/차감 방향은 콘솔이 상태 하나로 소유하고, 세그먼트·하단 바 라벨·키보드 단축키가 공유한다
- 성공 피드백은 세 경로(확인 버튼·하단 바·숫자 단축키) 모두 같은 토스트 하나: `+10분 · 벌칙룰렛` + '되돌리기' 버튼(6초, 마우스·포커스가 올라가 있는 동안 유지). 결과 잔여 시간은 카운트다운과 겹치므로 넣지 않는다. '되돌리기'는 반대 방향 변경이 아니라 그 기록의 취소 처리(`POST /api/timers/[id]/logs/[logId]/revert`)라 기록에 보정 행이 생기지 않고, 그 행은 '되돌림'으로 표시되며 통계·그래프·목표에서 빠진다(`src/hooks/useUndoableModifyToast.ts`). 실수에 확인 대화상자나 차감 모드 자동 복귀를 두지 않고 되돌리기로 푼다(C015 결정: 바의 부호·빨강·캡션이 모드를 이미 보여 준다)
- 토스트는 한 번에 하나이고 새 토스트가 이전 것을 바로 교체한다(연속 조작에서 쌓이지 않게). 모바일 하단 바가 있으면 바 바로 위(`--quick-bar-h`와 safe-area 중 큰 쪽)에 뜬다. md 이상에서는 컨테이너 폭을 `max-w-sm`으로 제한한다. 'R' 새로고침은 완료 토스트를 띄우지 않는다
- 실패 피드백은 한 곳에만 띄운다(C032). 확인 버튼으로 제출했고 그 버튼(오류 문구는 바로 위)이 화면 안(모바일은 하단 바 위)이면 인라인 `role=alert`, 요청 중 스크롤해 화면 밖이면 토스트. 하단 바·숫자 단축키의 적용 실패는 늘 토스트. 5xx·네트워크 실패는 '적용하지 못했습니다. 입력은 그대로 있으니 다시 확인을 누르세요.'(바·단축키는 '…다시 눌러 주세요.'), 4xx는 다시 눌러도 안 되므로 서버가 준 이유(만료된 타이머 차감 등)를 그대로 쓴다. 확인 버튼·Enter로 닉네임 없이 제출하면 인라인 '시청자 닉네임을 입력해 주세요.' 한 문구(바가 띄운 입력란 안내가 이미 보이면 겹쳐 띄우지 않는다). 닉네임 없이 누른 하단 바·숫자 단축키는 실패가 아니라 입력란 안내다(위 W32 항목·단축키 표)
- 401은 시간 변경 경로(확인 버튼·하단 바·숫자 단축키·되돌리기·지금 시작)가 아무것도 띄우지 않고 세션 만료 토스트('세션이 만료되어 로그인 화면으로 이동합니다.') 한 건만 남긴다(C029). 화면 값·입력은 되돌린다. 로그인 화면은 만료로 왔을 때(`expired=1`)만 '세션이 만료되어 다시 로그인합니다.' 한 줄(`role="status"`)을 보인다
- 키보드 단축키 (소유자, RUNNING/EXPIRED, 입력 필드 밖에서만. 화면에 모달(`dialog[open]` 또는 `aria-modal="true"`)이 열려 있으면 숫자키와 X는 꺼진다. 목표 폼·삭제 확인·오버레이 설정 위에서 뒤쪽 타이머가 바뀌지 않게 하기 위해서다)

  | 키 | 동작 |
  |---|---|
  | `1` / `5` / `0` | 입력한 시청자 닉네임(비어 있으면 기본 닉네임)으로 1/5/10시간을 선택한 방향(추가·차감)으로 즉시 적용. 둘 다 없으면 적용하지 않고 닉네임 입력란으로 포커스를 옮기며 토스트 '닉네임을 먼저 입력하세요' 한 문장. 만료 중에는 늘 추가 |
  | `X` | 추가/차감 전환(만료 중에는 세그먼트가 없어 동작하지 않는다) |
  | `R` | 수동 새로고침 |
  | `?` | 단축키 도움말 |

  단축키를 외우지 않아도 찾을 수 있게 '시간' 제목 줄 오른쪽에 '단축키' 링크 버튼(`Button variant="link"`) 하나가 도움말을 연다. 키보드가 있는 포인터 기기(`pointer: fine`)에서만 보인다. 터치 기기에서는 CSS로 숨기고, 단축키가 꺼진 예약 상태와 시청자 화면에서는 렌더하지 않는다. 프리셋 칩에는 키 표시를 붙이지 않는다(칩은 입력값에 더하고 숫자키는 즉시 적용해 동작이 다르다). `aria-keyshortcuts="X"`는 추가/차감 세그먼트의 두 라디오에만 둔다(포커스를 받는 요소라야 스크린리더가 읽는다). 도움말 각주는 한 문장 '숫자키는 닉네임 칸의 이름(없으면 기본 닉네임)으로 바로 적용됩니다.'이다. 기본 닉네임 설정 안내는 그 버튼이 보이는 입력란 옆 한 줄이 맡는다.

  X·R은 한국어 IME가 켜져 있어도 동작하도록 문자 대신 `e.code`(`KeyX`/`KeyR`)로 판별한다. 모든 단축키는 Cmd/Ctrl/Alt 조합을 무시해 브라우저 단축키(Cmd+1 탭 전환, Cmd+R 새로고침)를 막지 않는다. Tab은 포커스 이동에 쓰므로 단축키로 쓰지 않는다. 목록은 `SHORTCUT_HELP`(`src/hooks/useKeyboardShortcuts.ts`)와 맞춘다.

#### 용어 (콘솔)
| 개념 | 표기 | 쓰지 않는 말 |
|---|---|---|
| 행위 | '시간 추가'·'시간 차감' | '시간 조작'(제목은 '시간') |
| 결과물 | '기록'(목록 제목 '최근 기록', 펼치면 '기록') | '변경 기록'·'최근 변경' |
| 추가/차감 선택 | 세그먼트(스크린리더 라벨만 '변경 유형', 화면에는 보이지 않는다) | |
| 삭제·초기화 문구 | '타이머·목표·기록', 메뉴 '타이머 초기화(목표 유지)' | '목표 기록 유지' |
- 타이머 삭제 확인창의 '목표 기록은 남습니다'는 결과 설명이라 그대로 둔다
- 공개 문구에는 CHZZK·치지직을 쓰지 않는다(로그인 안내는 예외)
- 섹션 제목(h2)은 `text-base font-semibold` 한 양식이고 accent 세로 막대를 쓰지 않는다. 시간 카드는 `border-border bg-background`(중립 카드)다. `--surface`·`--surface-elevated` 토큰은 정의하지 않았다(메뉴·모달·토스트는 기존 토큰 그대로). 예약 상태의 시간 카드는 안내·버튼 하나뿐이라 제목을 숨기고(상태는 배지·보조 문구가 알린다) 카드는 `aria-label="시간"`으로 남긴다. 만료 상태는 재시작 안내와 입력 폼이 모두 보이므로 제목을 둔다
- 빈 상태: 목표가 0건(받은 결과 기준)이면 탭·안내문 없이 '새 목표' 버튼과 한 줄만, 타이머 전체에 기록이 0건이거나 CREATE뿐이면(필터 없는 첫 페이지 기준) '전체 기록'·필터 칩을 숨긴다. 오류 중, 이미 펼친 뒤에는 숨기지 않는다. '전체 기록'은 기록이 있다고 판정된 뒤에만 그린다(첫 조회 중에 그렸다가 지우면 깜빡인다)
- 콘솔 위 행(시간 | 목표)과 아래 행(기록 | 그래프)은 같은 3:2 트랙(`lg:grid-cols-[minmax(0,3fr)_minmax(0,2fr)]`)·열 간격 `gap-x-5`라 열 경계가 맞는다. 세로 간격은 `gap-y-8`로 위 행·아래 행·카운트다운 사이(`space-y-8`)와 같아, 한 열로 쌓이는 모바일에서도 섹션 사이가 32px 하나다. 섹션 제목 줄은 모두 24px(제목 높이)이고 제목→내용은 12px(`mt-3`·`space-y-3`)다. 제목 줄 안의 버튼('새 목표'·'전체 기록')은 음수 여백으로 줄을 키우지 않는다. '새 목표'(40/44px)는 아래로 넘친 만큼(8/10px) 제목 줄에 padding을 두어 아래 탭·안내와도 12px을 남긴다. 시간 카드의 프리셋 칩은 같은 줄의 시·분·초 입력과 같은 높이(데스크톱 40px, 터치 44px)다. 시간 카드와 그래프 상자는 같은 양식(`rounded-card border border-border bg-background p-5`)이고, 목표·기록 행의 구분선은 `border-border/50` 하나다. 시간 카드의 입력 묶음 이름('변경할 시간')은 스크린리더용이라 보이지 않고, 칸 이름은 '시'·'분'·'초'다(옆의 단위 글자가 `<label htmlFor>`로 입력과 이어져 있고, 새 타이머 폼의 초기 시간 칸도 같은 이름이다)

#### 기록
- 기본은 '최근 기록' 5건. '전체 기록'(링크 버튼)으로 펼치면 '기록'(20건 단위 페이지네이션)과 필터 칩 3개가 생긴다: '추가'(ADD), '차감'(SUBTRACT), '기타'(CREATE·EXPIRE·REOPEN·ACTIVATE). 여러 개 동시 선택, `aria-pressed`, '초기화'. 삭제된 타이머는 기록을 볼 수 없어 DELETE 칩은 두지 않는다(API의 `actionType`은 그대로 받는다)
- 각 행: 액션 뱃지, 시청자(되돌린 행은 '· 되돌림'), 변경량, 시각, 변경 전 → 후. 최근 순
- 시각은 오늘이면 `HH:mm`만, 오늘이 아니면 `MM. DD. HH:mm`(다른 해면 연도까지). 초까지의 전체 시각은 `<time>`의 title(`formatLogTime`, `src/lib/utils.ts`)
- 액션 타입별 색상 뱃지 (텍스트 병행)
  - 색은 앱 전체 배지와 같은 의미 축을 쓴다(아래 '배지 색'): ADD(추가) 초록, SUBTRACT(차감)·EXPIRE(만료) 빨강, CREATE(생성)·REOPEN(재시작)·ACTIVATE(활성화)·DELETE(삭제) 회색

- 잔여 시간 추이(`RemainingChart`) 하나. 누적 변경량은 통계 화면에 있고, 이벤트 빈도는 통계의 시간대별 변경 횟수와 겹쳐 없앴다

#### OBS 오버레이 설정 (`OverlaySettings`)
- 네이티브 `<dialog>`를 `showModal()`로 연다(배경 inert·Tab 순환은 브라우저가 맡는다). 미리보기·URL이 들어가야 해서 `FormDialog`(28rem)가 아니라 max-w-2xl 시트와 하단 고정 영역을 따로 둔다. md 미만에서는 가운데 카드 대신 화면 아래에 붙은 시트(좌우 꽉 채움, 위쪽 모서리만 둥글게, 최대 90dvh)이고, 헤더·푸터 패딩을 줄이고 푸터 아래에 safe-area만큼 띄운다. Esc·배경 클릭·닫기 버튼은 저장 안 한 변경이 있으면 확인창을 거치고, 닫히면 연 버튼으로 포커스를 돌려준다
- 현재 상태를 컨트롤 자체로 보여 준다: 설정이 프리셋 값(색·배경·그림자·크기)과 같으면 그 프리셋이 눌린 상태(`aria-pressed`, 체크 표시). 프리셋은 값을 한꺼번에 바꾸는 즉시 적용 버튼이라 secondary 버튼 모양이고, 선택 컨트롤(세그먼트)처럼 칠하지 않는다. 위치 칸 5개는 상시 윤곽(배경 대비 3:1 이상)에 고른 칸만 채움, 투명 배경은 견본을 체커보드로 그리고 '투명으로 초기화'는 투명이 아닐 때만 보인다
- 순서는 URL → 미리보기 → 설정이다. URL은 무엇이 복사되는지 확인하는 자리(읽기 전용, 선택 가능)이고, 아래 한 줄이 'OBS 브라우저 소스에 붙여넣기 · 너비 1920 높이 1080'을 안내한다. OBS 브라우저 소스의 기본 크기(800×600)로 두면 위치가 어긋나기 때문이다
- 하단 고정 주 버튼은 'URL 복사' 하나다. 오버레이는 URL 파라미터만 읽어 방송에 반영하는 길이 복사·붙여넣기뿐이므로, 누르면 변경을 저장하고 새 URL을 복사한 뒤 'URL을 복사했습니다. OBS에 붙여넣으세요'를 알린다. 클립보드 쓰기는 클릭 직후(await 전)에 시작한다(Safari는 await 뒤 사용자 활성화를 잃는다). 복사 실패와 저장 실패는 따로 알리고, 저장이 실패하면 변경 상태를 남긴다. 제목과 설정은 따로 보내 하나가 실패해도 다른 하나는 저장한다. 빈 제목은 저장하지 않지만 복사·설정 저장은 막지 않는다. 저장 중에는 변경 취소를 막는다. 변경이 있으면 푸터에 '복사하면 변경 사항도 저장됩니다'와 '변경 취소'가 보인다
- 미리보기는 오버레이를 1920×1080 iframe으로 그려 16:9 상자 폭에 맞춰 `transform: scale`로 줄인다(상자 폭은 ResizeObserver로 잰다). 크기·위치가 방송 화면 비율 그대로 보인다. 폭 768px·높이 896px 이상에서는 스크롤 영역 위쪽에 붙어(sticky) 아래 설정을 바꾸는 동안에도 보인다. 그 높이만큼 scroll-padding-top을 둬 Tab으로 이동한 컨트롤이 미리보기 아래로 숨지 않게 한다. 배경이 투명이면 미리보기는 어두운 회색(#3f3f46) 위에 그리고, '미리보기' 옆 '밝은 화면에서 보기' 토글(aria-pressed)로 흰 배경 위에서도 볼 수 있다. 밝은 게임·캠 화면에서 글자가 읽히는지 확인하는 용도라 설정·URL에는 넣지 않는다. 밝은 배경에서 글자색을 어둡게 자동으로 바꾸지는 않는다(글자색은 스트리머가 고른다)
- '제목 표시'를 켜면 '표시할 제목'(타이머 제목, 1~100자)을 고칠 수 있다. 저장 전 변경·닫기 경고에 포함되고, '제목 표시'를 끄면 고친 제목은 되돌린다(보이지 않는 값을 저장하지 않게). 제목은 오버레이가 폴링으로 다시 읽어 URL과 무관하므로, 제목만 바뀌었을 때 주 버튼은 '제목 저장'이 되고 복사 없이 저장만 한 뒤 '다시 붙여넣지 않아도 됩니다'를 알린다

### 3. 타이머 주소 (`/timers/[id]`)

서버 컴포넌트가 D1에서 타이머를 찾아 상위 프로젝트(`/projects/[projectId]`)로 `redirect()`한다. 타이머 조작을 프로젝트 화면으로 합친 뒤에도 예전에 공유한 타이머 주소가 계속 열리게 하기 위해서다. 클라이언트 골격·`router.replace`를 거치지 않아 도착한 화면의 제목·상태가 바로 최종 값이다. Next의 `redirect()`는 임시 3xx(현재 307)를 내며, 302로 억지로 맞추지 않는다. 없는 타이머(삭제 포함)면 `notFound()`로 HTTP 404·noindex를 내고 같은 폴더의 `not-found.tsx`가 안내(`ErrorState`)를 그린다(200으로 그리면 soft 404). 탭 제목 '찾을 수 없음 | 삼루먼타이머'는 page의 metadata가 맡는다(하위 not-found의 metadata는 쓰이지 않는다). DB 오류는 잡지 않고 `app/error.tsx`의 '다시 시도'에 맡긴다. 오버레이(`/timers/[id]/overlay`)와 통계(`/timers/[id]/stats`)는 타이머 주소에 그대로 있다.

### 4. 타이머 통계 (`/timers/[id]/stats`)

- 요약 카드(`StatsCardGrid`), 상위 시청자(`DonorRankingTable`), 누적 변경량(`CumulativeChart`, 불러오지 못하면 이 섹션만 숨긴다), 시간대별 변경 횟수(`HourlyActivityChart`), 일별 활동 30일(`DailyActivityChart`)
- 용어는 콘솔과 같다: 시간을 바꾼 사람은 '시청자', 더한 시간은 '추가 시간', 기록 건수는 '변경 횟수'
- 요약 카드: 순 추가 시간은 숫자에 부호(`+12시간 50분`)를 넣고, 숫자를 되풀이하는 보조문구는 두지 않는다(추가한 시청자의 '고유 닉네임 기준'만 남긴다). 이 카드는 ADD 기록의 고유 닉네임만 세므로 '시청자 수'가 아니라 '추가한 시청자'다
- 순위는 모두 숫자, 1~3위만 굵게. 표는 `max-w-2xl`로 폭을 제한한다
- 추가는 초록·0선 위, 차감은 빨강·0선 아래(시간대별·일별 막대는 `stackOffset="sign"`로 음수 막대), 누적 변경량의 차감은 점선. 범례에 `+`/`-` 부호를 붙여 색 없이도 갈린다
- 일별 활동은 마지막 기록일까지 30일을 빈 날 0으로 채운 고정 축이다. 창이 오늘이 아니라 마지막 기록일에서 끝나므로 제목에 '최근'을 쓰지 않고, 기간은 축 날짜와 aria 요약으로 보인다. 막대 폭은 `maxBarSize` 24px. Y축은 콘솔 그래프와 같은 `durationAxisTicks`·`formatDurationTick`('4시간', '30분')
- 제목은 프로젝트 이름 기준(「프로젝트 이름 통계」), 복귀 링크는 프로젝트 화면

### 5. 오버레이 (`/timers/[id]/overlay`)

OBS 브라우저 소스용. 앱 크롬(헤더·푸터) 없이 카운트다운을 렌더링한다. 배경은 기본 투명이고 글꼴 크기·색·배경·위치 등은 쿼리 파라미터로 정한다. 탭 제목은 다른 화면과 같은 모양의 '{타이머 제목} 오버레이 | 삼루먼타이머'(`pageTitle()`)다.

**서체와 보조 줄**: 숫자(카운트다운·변경량 '+1:00')만 Geist Mono이고, 제목·'종료 예정'·'만료됨'·'시작 대기 중' 같은 보조 줄은 본문 산세리프(Noto Sans KR)다. 한글까지 고정폭이면 종료 예정 줄이 카운트다운의 두 배 가까이 넓어진다. 카운트다운과 종료 예정 시각은 `tabular-nums`. 보조 줄은 불투명·굵기 600이고, 그림자를 켜면 짧은 그림자를 겹친 외곽선형(`0 0 3px rgba(0,0,0,.9)` 두 번 + 기존 drop)을 둘러 밝은 방송 화면에서도 번지지 않게 한다. 종료 예정 줄은 콘솔 카운트다운과 같은 `formatEndTime`(`src/lib/utils.ts`)으로 '종료 예정 오후 1:33'(오늘)·'종료 예정 10. 6. 오후 1:33'(다른 날)·'종료 예정 2027. 1. 2. 오전 1:05'(다른 해)이다. 시각은 처음 받은 응답과 시간·상태가 바뀐 응답(`updatedAt`·`status`)에서만 다시 잡는다. 폴링마다 다시 재면 서버 잔여시간의 초 내림·응답 지연으로 분 경계에서 바뀌었다 돌아온다. 생성·예약 시각부터 잰 경과는 만료 뒤 다시 시작한 타이머에서 틀리므로 붙이지 않는다. 100시간을 넘어도 '일' 단위로 바꾸지 않고 시간으로 센다(99시간 마라톤이 흔하고 콘솔과 같은 포맷을 쓴다).

**변경 연출** (`src/lib/overlay-animation.ts`): 폴링 사이에 시간이 추가·차감되면 숫자가 한 번 번쩍이고(추가는 커지고 초록, 차감은 흔들리고 빨강) 변경량('+1:00')이 1.2초 동안 떠올랐다 사라진다. 변경량은 숫자 줄의 안쪽 옆(오른쪽 배치는 숫자 왼쪽, 나머지는 오른쪽)에 붙고 숫자 줄 높이 안에서만 움직인다. 위로 띄우면 제목과 겹치고 위쪽 배치에서 화면 밖으로 잘리며, 아래로 띄우면 '만료됨'·'종료 예정' 줄과 겹치고 아래쪽 배치에서 잘리기 때문이다. 값은 직전 `updatedAt`을 `since`로 보내 받은 `GET /api/timers/[id]?since=`의 `deltaSinceSeconds`(그사이 추가·차감의 실제 변경량 합계)를 쓴다. 폴링 시각으로 추정하면 1~2초 어긋나 '+60초'가 '+1:01'로 보이고, 만료·재오픈이 끼면 더 어긋난다. 실제 값이라 오차 범위 없이 0이 아니면 연출하고, `null`(그사이 추가·차감 없음)이면 연출하지 않는다. 필드가 없을 때(이전 서버, 계산할 수 없는 since, 그사이 되돌리기가 있었던 경우, 겹친 응답으로 기준이 바뀐 경우)만 경과 시간 반올림으로 추정하고 ±2초 안은 시간 흐름의 오차로 보고 넘긴다.

방송 화면에는 오류 문구를 그리지 않는다. 실패는 브라우저 콘솔에 `console.warn`으로만 남기고, 같은 원인(상태 코드·네트워크 오류·해석 실패)은 바뀔 때 한 번만 남긴다.

실패해도 대개는 마지막으로 받은 값을 유지하고 로컬 카운트를 이어 간다(5xx·네트워크 오류는 곧 회복되는 경우가 많다). 예외는 404·410(타이머 삭제·URL 오류)이다. 이때는 카운트다운을 지워 설정한 배경만 남긴다. 삭제된 타이머의 시간을 계속 세면 거짓 시간이 방송에 나가기 때문이다. 타이머 초기화 확인 창도 "방송 화면의 오버레이가 사라집니다"로 이 동작을 알린다.

**폴링** (`src/lib/overlay-polling.ts`): 성공하면 5초 간격. 실패가 이어지면 간격을 두 배씩 늘리고(10초 → 20초 → …) 성공하는 즉시 5초로 돌아간다. 오버레이는 방송 내내 켜져 있어서, 실패한 채 5초마다 두드리면 Workers 무료 요청 한도(하루 10만)를 낭비하기 때문이다. 상한은 원인별로 다르다.

| 원인 | 상한 |
|---|---|
| 404·410 (타이머 삭제·URL 오류) | 5분 |
| 429, 200인데 JSON이 아니거나 `data`가 없는 응답 | 5분 |
| 5xx, 그 밖의 실패 응답(401·403 포함), 네트워크 오류, 응답 처리 중 예외 | 60초 |

200이어도 본문이 JSON이 아니거나 `data`가 없으면 5분 상한으로 다룬다. 실패 상태 코드는 본문 형식과 무관하게 상태 코드로만 판정한다(프록시·CDN의 HTML 502/503/504는 60초 상한). `/api/timers/[id]`는 공개 엔드포인트라 401·403에 별도 분기를 두지 않고 그 밖의 실패 응답(60초 상한)으로 다룬다. 재귀 `setTimeout`으로 다음 요청을 예약하고, 언마운트하면 예약을 지우며 응답을 기다리던 중이면 다음 요청을 예약하지 않는다.

**렌더 오류** (`overlay/error.tsx`, `src/lib/overlay-recovery.ts`): 아무것도 그리지 않고 투명 배경과 오버레이 모드(`src/lib/overlay-mode.ts`)를 다시 적용한다. 페이지가 언마운트되며 이를 지우기 때문이다. `reset()`을 5초부터 두 배씩, 최대 60초 간격으로 다시 시도하고, 5번 실패하면 `location.reload()`한다. reload는 `sessionStorage` 카운터로 장애당 2번까지만 하고(저장소를 읽거나 쓸 수 없으면 하지 않는다), 그 뒤에는 60초 간격 `reset()`을 계속한다. 타이머를 그린 뒤 5분 동안 렌더 오류 없이 버텨야 회복으로 보고 횟수와 상한을 되돌린다. 그리기만 하면 바로 되돌리면, 데이터를 그린 다음에야 터지는 오류에서 백오프와 reload 상한이 매번 처음부터 시작돼 끝없이 돈다. 같은 오류가 5분 넘게 정상으로 버틴 뒤에야 다시 난다면 그때마다 새 장애로 보고 reload를 다시 2번까지 한다. `retry()`는 매번 RSC 요청을 보내므로 쓰지 않는다. 루트 레이아웃에서 난 오류는 `global-error.tsx`가 받는데, 오버레이 경로이면 투명한 빈 화면만 그리고 같은 정책(`src/hooks/useOverlayRecovery.ts`)으로 `reset()`·reload를 자동으로 시도한다.

PWA 서비스워커는 OBS 브라우저 소스에서 등록하지 않는다. 이미 SW가 있는 브라우저(설정 화면의 iframe 미리보기, 오버레이 URL을 직접 연 탭)에서도 오버레이 문서 요청과 그 문서가 보낸 청크 요청(referrer가 오버레이)은 가로채지 않는다. 예외로 CSS가 부르는 폰트는 referrer가 CSS 파일이라 해시 정적 자산 캐시를 탈 수 있다. 방송 화면에 오프라인 안내나 오래된 시간이 나가지 않게 하기 위해서다 (`docs/ARCHITECTURE.md`의 PWA 절).

### 6. 로그인 (`/login`, `/callback`)

CHZZK OAuth 로그인 진입 페이지. OAuth 콜백은 `/api/auth/callback`이 처리하고, `/callback` 페이지는 직접 들어오면 `/`로 보내기만 한다.

- 본문은 `SignInScreen`(`src/components/layout/`)이고 로그아웃 `/projects`와 같다. 첫 화면 60% 높이 안 가운데에 제목·부제·버튼을 두며, 가운데 정렬 글은 `text-balance`로 줄 길이를 고르게 나눈다(마지막 줄에 한두 낱말만 남지 않게)
- 제목·부제는 사이트 설명(`SITE_TAGLINE`·`SITE_SUMMARY`)이고, 플랫폼 이름은 'CHZZK로 로그인' 버튼에만 쓴다. 브랜드명은 헤더 로고가 이미 보여 준다
- 로그인 버튼은 주 CTA라 공용 Button md(primary, 40px·터치 44px, 16px 글자)를 폭 전체로 쓴다. 따로 만든 48px·14px 버튼을 두지 않는다
- 헤더의 '로그인' 링크는 이 화면에서 숨긴다(같은 화면을 다시 열 뿐이라)
- `?error=`면 실패 안내, 동의 화면 취소는 안내 없이 돌아온다. `?next=`는 로그인 버튼이 들고 간다
- 이미 로그인한 상태면 `next`(없으면 `/projects`)로 보낸다. `?error=`가 있으면 머문다

### 렌더 오류 경계

- `src/app/error.tsx`: 루트 레이아웃 아래 페이지의 렌더 오류. 헤더·푸터는 그대로 두고 본문을 `ErrorState` 안내로 바꾸며, 서버 로그와 맞춰 볼 수 있게 `digest`를 '오류 코드'로 보여 준다. '다시 시도'는 서버 컴포넌트까지 다시 받는 `retry()`를 쓴다.
- `src/app/global-error.tsx`: 루트 레이아웃(Header·Provider)에서 난 오류. 루트 레이아웃을 대신하므로 자체 `html`/`body`와 인라인 스타일을 쓴다. 탭 제목은 `pageTitle('오류')`('오류 | 삼루먼타이머'). 오버레이 경로에서는 투명한 빈 화면만 보이게 하고, OBS에서는 아무도 버튼을 누르지 않으므로 오버레이 오류 경계와 같은 백오프·reload 상한으로 스스로 복구를 시도한다. 서버 렌더에서도 문구가 비치지 않도록 head 인라인 스크립트(클라이언트 렌더에서는 `useLayoutEffect`)가 `html[data-overlay]`를 붙이고 CSS로 숨긴다.
- 오버레이는 자체 경계를 둔다(5절).
- 렌더 오류는 브라우저에서만 일어나 서버 로그에 남지 않는다.

### 찾을 수 없음·권한 없음

아이콘 원이 있는 가운데 상태 블록(빈 목록, 상세의 타이머 없음, 찾을 수 없음, 불러오기 실패)은 모두 `StatePanel` 하나의 규격이다: 원 56px·아이콘 28px(중립 `bg-foreground/5`, 오류 빨강), 위아래 48px, 원→제목·문구 16px, 제목→문구 4px, 글→행동 16px, 가운데 정렬 글은 `text-balance`. 손으로 쓴 다른 크기의 원을 두지 않는다. 글만 있는 상태('검색 결과가 없습니다.')는 원 없이 같은 위아래 48px·16px 문구다.

`ErrorState`(`StatePanel`을 감싼다)는 두 톤을 쓴다. 다시 시도로 풀릴 수 있는 실패(불러오기 실패, 렌더 오류)는 빨간 아이콘과 '다시 시도'(`tone="error"`, 기본). 다시 시도해도 결과가 같은 안내(없는 경로, 없는 프로젝트·타이머, 비소유자 통계)는 중립 아이콘·h1·돌아갈 링크 하나(`tone="neutral"`, `title`, `action`)다. 로그인 버튼은 헤더에 있으므로 본문에 두지 않는다. 골격이 첫 화면을 채우는 화면(프로젝트 상세)은 못 찾음·실패 안내도 같은 첫 화면 높이(`FILL_FIRST_SCREEN`) 안에 그린다. 짧은 안내로 바뀌며 첫 화면 밖의 footer가 올라오는 이동을 막기 위해서다(390 폭 CLS 0.048 → 0).

화면 일부만 실패하면(콘솔의 목표·기록·그래프) 그 섹션 본문에 `ErrorState compact` 한 줄('…를 불러오지 못했습니다 · 다시 시도')만 둔다. 데이터 초기값은 `null`(아직 받지 못함)로 두어 빈 결과(`[]`)와 구분하고, 빈 상태 문구·탭 개수 '(n)'은 2xx로 받은 결과에만 보인다. 실패를 '없습니다'·'(0)'으로 가리지 않기 위해서다. 이미 보이던 데이터는 백그라운드 갱신(폴링·30초 주기)이 실패해도 오류로 바꾸지 않는다. 오류 줄은 연결이 돌아올 때(끊김 → 복원), 다음 폴링 성공 때(기록·그래프), 30초 주기(목표)에 조용히 다시 불러와 저절로 사라진다.

- `src/app/not-found.tsx`: 없는 경로. 루트 레이아웃 안이라 헤더·푸터·앱 배경이 그대로다. 탭 제목은 다른 못 찾음 화면과 같은 '찾을 수 없음 | 삼루먼타이머'. h1 '페이지를 찾을 수 없습니다' + 한 문장('삭제되었거나 주소가 잘못되었습니다.') + '프로젝트 목록으로'(아이콘·한 문장·버튼 하나).
- 없는 프로젝트(`/projects/[id]`)·타이머(`/timers/[id]`): '…를 찾을 수 없습니다' + '프로젝트 목록으로'.
- 통계(`/timers/[id]/stats`): 401(로그아웃·세션 만료)이면 '로그인이 필요합니다', 403이면 '통계를 볼 수 없습니다'(소유자만) + '프로젝트로 돌아가기'(타이머 조회가 실패하면 '프로젝트 목록으로'), 404면 '타이머를 찾을 수 없습니다'. 세션 만료(`SESSION_EXPIRED`)는 세션 만료 흐름도 함께 탄다. 탭 제목은 401·403 '통계를 볼 수 없음 | 삼루먼타이머', 404 '찾을 수 없음 | 삼루먼타이머'. 로드 실패(5xx·네트워크)는 h1 '통계'와 돌아갈 링크를 남기고 본문만 '다시 시도' 오류로 바꾼다.

- 다이얼로그 셸: 제목은 h2, 닫기(X)는 44px 히트 영역. 폼 다이얼로그(`FormDialog`)는 X가 닫기를 맡으므로 푸터에 취소 버튼 없이 주 동작 하나를 오른쪽에 둔다. 확인창(`ConfirmDialog`)은 같은 제목 양식에 X 없이 '물러서기 + 주 동작'을 오른쪽에 둔다

문구 규칙:
- 확인창(`ConfirmDialog`) 본문은 결과만 적는다('정말로 …하시겠습니까?'를 쓰지 않는다). 결과는 사용자가 잃는 것을 빠짐없이 적는다(프로젝트 삭제는 타이머·목표·기록). 서버는 소프트 삭제지만 사용자가 다시 볼 길이 없으므로 '지워진다'고 쓴다. 확인 버튼은 대상을 담은 동작명(예: '프로젝트 삭제'·'목표 취소'·'목표 삭제'. 타이머 쪽 이름은 더보기 메뉴 항목과 같은 이름을 쓴다), 빠져나가는 버튼은 모든 확인창에서 '돌아가기'(기본값)다. '취소'가 목표 취소 동작과 겹치지 않게 하려는 것이다
- 타이머 제목은 어디서나 '제목'이라 부른다(오버레이 설정의 '제목 표시', 새 타이머의 '제목 (필수)')
- 불러오기 실패는 '~를 불러오지 못했습니다.', 요청형은 '~해 주세요', 말줄임은 '…'(U+2026)
- 사용자에게 CSS 값을 그대로 보이지 않는다. 오버레이 배경색 칸은 저장값 `transparent`를 '투명'으로 보이고 '투명' 입력도 받는다

테마는 `src/lib/theme.ts`의 `applyTheme` 하나로 정한다. 저장값(`localStorage.theme`)이 `light`·`dark`면 그대로, `system`이거나 없으면 OS 설정을 따라 html에 `dark`·`light` 중 정확히 하나만 붙인다. 레이아웃의 첫 페인트 전 인라인 스크립트도 같은 함수 소스를 실행한다. `ThemeToggle`은 라이트 → 다크 → 시스템 순으로 돌고, 이름은 "테마: 다크 (눌러서 시스템으로)"처럼 지금 상태와 다음 동작을 함께 알린다.

## Recharts 그래프 설계

### 공통 축·접근성

- X축: 로그 발생 시각(ms)을 `type="number" scale="time"`으로 그린다. 기록 순번(category 축)으로 그리면 같은 분에 몰린 기록과 몇 시간 뒤 기록이 같은 간격이 되고, 눈금 라벨이 같은 값으로 되풀이된다. 눈금은 `buildTimeAxis`(`src/lib/utils.ts`)가 로컬 시각의 깔끔한 경계(5분·1시간·3시간·자정 등)에 최대 5개 두고, 라벨은 `HH:mm`이다. 눈금이 여러 날에 걸치면 첫 눈금과 날짜가 바뀌는 눈금에만 `MM. DD.`를 붙인다
- Y축: `durationAxisTicks`가 0부터 정수 시간(1·2·3·4·5·6·10·12·…·25·50·100시간) 또는 분(1·2·5·10·15·30분) 간격으로 최대 4칸을 만들고, 라벨은 `4시간`·`30분`처럼 한국어 한 단위다
- 접근성: Recharts `accessibilityLayer={false}`로 내부 Tab 정지점·눈금 나열 이름을 없애고, 감싸는 `role="img"`의 `aria-label`에 요약을 넣는다(잔여: 기록 수·마지막 기록·최고값, 누적: 누적 추가·차감)

### 잔여 시간 추이 (LineChart, 콘솔)

```tsx
<LineChart data={points} accessibilityLayer={false}>
  <XAxis dataKey="t" type="number" scale="time" ticks={...} />
  <YAxis ticks={durationAxisTicks(max)} />
  <Tooltip />
  <Line type="stepAfter" dataKey="remainingSeconds" stroke="var(--color-accent)" />
</LineChart>
```

- 점: 각 로그 이벤트 시점의 변경 후 잔여 시간(`after_seconds`)
- stepAfter 보간: 이벤트 시점에 값이 바뀐다. 실행 중 자연 감소는 그리지 않는다(점 사이가 평평하다)
- 선 색은 앱 강조색 토큰(`--color-accent`)
- 모든 그래프 툴팁은 `graph/tooltip-style.ts`의 `chartTooltipStyle`을 펼쳐 쓴다. 값 글자는 계열 색(라이트에서 `#22c55e`는 2.3:1)을 따르지 않고 본문색(`--color-foreground`)이다

### 누적 변경량 (AreaChart, 통계 화면)

```tsx
<AreaChart data={points} accessibilityLayer={false}>
  <XAxis dataKey="t" type="number" scale="time" ticks={...} />
  <YAxis ticks={durationAxisTicks(max)} />
  <Tooltip />
  <Area type="stepAfter" dataKey="totalAdded" fill="green" />
  <Area type="stepAfter" dataKey="totalSubtracted" fill="red" />
</AreaChart>
```

- 누적 추가량 (초록 영역)과 누적 차감량 (빨강 영역·점선)을 겹쳐 표시. 범례는 '+ 누적 추가', '- 누적 차감'
- 누적량은 이벤트 시점에만 바뀌므로 stepAfter로 그린다. 곡선(monotone)은 이벤트 사이에 없는 중간값을 그린다

그래프 API(`/api/timers/[id]/graph`)는 `mode=frequency`(시간대별 변경 횟수)도 계속 지원하지만, 화면에서는 통계의 `HourlyActivityChart`가 같은 정보를 보여 주므로 쓰지 않는다.

## 반응형 디자인

| 브레이크포인트 | 레이아웃 |
|---------------|---------|
| < 640px (모바일) | 단일 열, 카운트다운 축소, 그래프는 컨테이너 폭에 맞춰 축소(ResponsiveContainer, 가로 스크롤 없음) |
| 640-1024px (태블릿) | 2열 그리드, 그래프 전체 폭 |
| > 1024px (데스크톱) | 3열 그리드, 콘솔의 시간·목표와 기록·그래프를 3:2로 나란히 |

- 320px 폭까지 가로 스크롤이 없어야 한다(WCAG 1.4.10). 시·분·초처럼 한 줄에 여러 칸을 두는 입력은 고정 폭(`w-20`) 대신 줄 폭을 나눠 쓴다(`[&>div]:flex-1 [&>div]:min-w-0` + 입력 `w-full`, `Input`이 div로 감싸여 있어서). 숫자 칸에는 `inputMode="numeric"`.
- 모바일 하단 고정 바의 높이는 `globals.css`의 `--quick-bar-h` 하나로 두고, body 하단 여백과 `scroll-padding-bottom`이 같이 쓴다. 그래서 Tab으로 포커스가 간 요소가 바 뒤에 숨지 않는다(WCAG 2.4.11). 바 높이를 바꾸면 이 변수만 고친다.

## 컨트롤 크기·모서리

- `Button` 크기는 역할로 고른다. `md`(기본값, 데스크톱 40px·터치 44px)는 주 CTA·다이얼로그 제출·헤더 액션, `sm`(32px·터치 44px)은 표·밀집 영역·칩, `lg`(48px)는 시간 추가 제출 하나다. 페이지네이션·확인 다이얼로그 버튼도 `md`다
- 텍스트 액션('전체 기록'·'단축키' 등)은 `variant="link"` 하나다. 인디고 14px, 밑줄은 hover에만. 보이는 높이는 글자 줄(데스크톱), 누르는 높이는 터치(`pointer-coarse:min-h-11`)에서만 44px다. 제목 줄 안에 두면 터치에서 줄이 커지므로 `pointer-coarse:-my-2.5`로 줄 높이를 지킨다. 전체 화면 오류(ErrorState 본형)의 '다시 시도'는 글자 링크가 아니라 막다른 404의 이동 버튼과 같은 `secondary` 버튼이고, 링크 모양은 카드 안 한 줄(compact)에만 쓴다
- 입력·select는 데스크톱 40px(`h-10`, Button `md`와 같은 줄 리듬), 터치 44px(`pointer-coarse:min-h-11`). 공용 `Input`, 목록 검색·정렬, 폼의 `selectClass`가 같은 규칙이다
- 비활성 버튼은 `opacity`로 흐리지 않고 중립 토큰(`bg-muted text-muted-foreground border-border`, ghost·link는 글자색만)으로 칠해 라이트·다크에서 같은 모양이다. 비활성 이유는 버튼 아래 힌트 문구로 알린다. 저장·생성 요청 중에 잠깐 막는 버튼은 `aria-busy`를 함께 넘겨 변형 색을 유지하고(hover만 빠지고 `cursor-wait`) '쓸 수 없음'과 구분한다
- `sm`이 남은 곳은 `touch-target.test.tsx`가 개수로 고정한다
- 모서리는 세 단계다. 컨트롤(버튼·입력·select·메뉴 항목) `rounded-control`(8px), 카드·다이얼로그 `rounded-card`(12px), pill `rounded-full`. 토큰은 `globals.css`의 `--radius-control`·`--radius-card`이고, `rounded`·`rounded-sm`·`rounded-md`(4·6px)와 `rounded-2xl` 이상은 쓰지 않는다(`radius-tokens.test.ts`가 방향 지정·임의값·CSS `@apply`까지 확인한다). 기존 `rounded-lg`·`rounded-xl`은 같은 값이라 손대는 파일부터 토큰으로 옮긴다
- `<Link>`가 버튼 모양이어야 하면 `buttonClassName({ variant, size })`를 쓴다(손으로 옮긴 클래스는 크기 규칙에서 어긋난다). 링크에는 `:disabled`가 없어 비활성 상태는 받지 않는다. 갈 수 없는 곳이면 링크를 렌더하지 않는다
- 헤더의 '로그인' 링크와 '로그아웃' 버튼은 같은 secondary 모양이다. 링크는 `buttonClassName({ variant: "secondary" })`로 Button과 같은 클래스를 만든다.
- `cn`은 tailwind-merge로 겹친 클래스를 풀어 뒤에 온 것만 남긴다(`cn("rounded-xl", "rounded-card")` → `rounded-card`). `utils.ts`의 `extendTailwindMerge`에 `globals.css` `@theme`의 커스텀 모서리·그림자 키를 등록해 둬서 `rounded-card`·`shadow-card`가 표준 클래스와 겹칠 때 풀린다(색 토큰은 기본 규칙이 색으로 읽어 따로 등록하지 않아도 `text-sm`과 `text-muted-foreground`처럼 다른 속성은 지워지지 않는다). `@theme`에 모서리·그림자를 더하면 `utils.ts`에도 더한다(`utils.test.ts`가 확인한다). Button의 크기·색·모서리는 그래도 className이 아니라 `variant`·`size`로 바꾼다. Button `md`·`sm`은 터치 `pointer-coarse:min-h-11`을 이미 가지므로 호출부에서 다시 붙이지 않는다

## 접근성 고려사항

- 시맨틱 HTML 사용 (button, nav, main, section)
- 색상만으로 상태를 구분하지 않음 (뱃지 텍스트 병행)
- 키보드 네비게이션 지원
- dev 서버(Turbopack)에서 `globals.css`의 `@custom-variant` 추가와 그 변형을 쓰는 파일 수정이 거의 동시에 일어나면(여러 파일을 한 번에 고칠 때) 새 변형의 클래스가 빠진 CSS가 남는다(2026-10-05 재현: 두 수정이 몇 초 떨어지면 반영되고, 몇 ms 안이면 순서와 관계없이 빠진다. 다음 `globals.css` 저장 때 함께 생긴다). 골격·로그인 힌트(`signed-out:`)처럼 새 변형이 dev에서 안 먹으면 `globals.css`를 한 번 더 저장하거나 dev 서버를 재기동한다. 프로덕션 빌드는 해당 없다
- 포커스 링은 `globals.css`의 `:focus-visible` 규칙 하나(`--ring` 2px outline, 간격 2px)다. 컴포넌트에 `focus-visible:ring-*`·`outline-none`을 달지 않는다(`focus-motion.test.ts`가 확인한다)
- `FormDialog`는 열린 뒤 자식의 `data-autofocus` 요소로 포커스를 옮긴다(새 목표=제목, 새 타이머=시간 칸). 닫힌 `<dialog>` 안에 미리 렌더된 자식의 React `autoFocus`는 showModal 전에 소모되어 듣지 않는다
- 탭(프로젝트 목록·목표)은 화살표 키로 선택과 포커스를 함께 옮긴다
- `prefers-reduced-motion: reduce`에서는 카운트다운 맥동을 끄고, `fade-in`·`toast-in`·`toast-out` 키프레임을 투명도만 바꾸는 것으로 다시 정의한다(다이얼로그·토스트·목록 카드가 이동 없이 나타난다). 추가/차감 세그먼트 썸은 미끄러지지 않고 바로 옮겨 간다. 스켈레톤 맥동은 그대로 둔다
- OS '대비 높이기'(`prefers-contrast: more`)에서는 `--border` 알파를 0.3으로, `--border-input`을 0.7(다크 0.6)로, `--muted-foreground`를 한 단계 진하게 바꾼다. 입력 경계를 함께 올려 카드(장식)와 입력(조작) 경계의 단차를 기본 테마 이상으로 남긴다(라이트·OS 다크·수동 다크 세 정의 모두. `contrast-tokens.test.tsx`가 확인한다)
- live region은 토스트가 둔 `role="status"` 하나(성공·정보 토스트와 카운트다운 임박 알림)와 오류용 `role="alert"`다. `role="status"`는 이미 polite라 `aria-live`를 덧붙이지 않는다
- 적절한 aria-label 사용
- 터치 타깃: 터치 기기(`pointer-coarse:`, 폰과 가로 태블릿 모두)에서 누르는 대상은 높이 44px 이상이다. 화면 폭(`max-md:`)이 아니라 입력 방식으로 가른다. 마우스 환경의 밀도는 그대로 둔다
  - 테두리·배경이 없는 대상(로고·내비 링크, 탭, 체크박스 행, 편집 중 저장·취소)은 `pointer-coarse:min-h-11`로 상자를 키운다. 보이는 모양은 같다
  - 보이는 크기를 바꾸면 줄 높이가 달라지는 대상(제목·설명 편집 연필)은 데스크톱에서 `p-2`로 히트 영역을 30px로 키우되 음수 여백(`-mb-1`)으로 줄 높이를 지키고, 글자와는 간격 4px(`gap-1`)를 두어 hover 배경 상자가 글자에 붙지 않게 하고, 터치에서는 `::before`를 넓혀 44px로 만든다(제목 전체를 누르는 영역으로 만들지는 않는다)
  - 문장 안 링크(푸터 이메일)는 `inline-block` + 같은 크기의 음수 여백으로 줄 높이를 바꾸지 않고 영역만 넓힌다
